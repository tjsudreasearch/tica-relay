# TiCa Relay 관리자 시스템 QA 기준

이 문서는 `Owner/Admin` 인증 레이어의 상세 검증 기준이다.
전체 기능 검수는 `docs/final-qa-checklist.md`를 기준으로 진행하고, 관리자 권한과 세션 보안은 이 문서의 항목을 함께 확인한다.

## 1. 핵심 불변조건

- `Owner`는 항상 정확히 1명이어야 한다.
- `Admin`은 0명 이상일 수 있다.
- `Owner`도 프로젝트 관리가 가능해야 한다.
- `Owner` 이전 시 기존 `Owner`는 자동으로 `Admin`이 되어야 한다.
- 모든 권한 검사는 화면이 아니라 서버에서 수행해야 한다.
- 참가자 또는 비인가 계정은 관리자 API에 접근할 수 없어야 한다.

## 2. 최초 관리자 생성

### 정상

- 최초 실행 후 첫 계정은 `Owner`가 된다.
- 초기 설정은 한 번만 가능하다.

### 검증

- 초기 설정을 새로고침해도 `Owner`가 여러 명 생기지 않아야 한다.
- 두 브라우저에서 동시에 초기 설정을 시도해도 정확히 한 계정만 생성되어야 한다.
- `관리자 수 > 0` 상태에서는 초기 설정 API가 차단되어야 한다.

## 3. 로그인과 세션

### 정상

- 로그인 성공 시 서버 세션이 발급된다.
- 로그아웃 시 세션이 즉시 폐기된다.
- 브라우저를 닫았다가 다시 열면 세션 정책에 맞게 동작한다.

### 검증

- 잘못된 비밀번호는 로그인되지 않아야 한다.
- 존재하지 않는 ID로는 로그인되지 않아야 한다.
- 로그인 실패가 계정 존재 여부를 과하게 드러내지 않아야 한다.
- 로그아웃 후 뒤로가기로 관리자 페이지에 접근할 수 없어야 한다.
- 세션 토큰은 다른 사람이 재사용할 수 없어야 한다.
- 비밀번호는 평문이 아니라 해시로 저장되어야 한다.

## 4. Admin 계정 생성과 삭제

### 생성

- `Owner`만 Admin을 추가할 수 있어야 한다.
- 중복 ID는 허용되지 않아야 한다.
- 빈 ID, 너무 짧은 비밀번호, 비밀번호 확인 불일치가 모두 차단되어야 한다.

### 삭제

- `Owner`만 Admin을 삭제할 수 있어야 한다.
- `Owner` 자신은 직접 삭제할 수 없어야 한다.
- 관리자 수가 0명이 되는 삭제는 허용되지 않아야 한다.

## 5. Owner 이전

### 정상

- 현재 `Owner`가 새 `Owner`를 선택할 수 있어야 한다.
- 이전 작업은 원자적으로 처리되어야 한다.
- 이전 직후 결과는 `기존 Owner = Admin`, `새 Owner = Owner`여야 한다.

### 검증

- `Admin`이 Owner 이전을 요청하면 거부되어야 한다.
- 두 요청이 동시에 들어오면 하나만 성공해야 한다.
- 이전 도중 서버가 꺼져도 `Owner`가 0명 또는 2명인 상태가 남지 않아야 한다.
- 기존 `Owner` 세션은 이전 후 재검증 또는 무효화되어야 한다.

## 6. 접근 제어 테스트

직접 URL로 접근해도 권한이 서버에서 막아야 한다.

- `/admin`
- `/admin/projects`
- `/admin/users`
- `/admin/settings`
- `/admin/logs`

### 테스트 행렬

| 페이지 | 참가자 | Admin | Owner |
| --- | ---: | ---: | ---: |
| 프로젝트 관리 | X | O | O |
| 관리자 관리 | X | X | O |
| 시스템 설정 | X | 제한 | O |
| 로그 | X | 제한 | O |

## 7. 권한 상승 공격

- 요청 바디에 `role=OWNER` 같은 값이 들어와도 서버가 거부해야 한다.
- 프론트에서 버튼을 숨기는 것만으로는 충분하지 않다.
- `projectId`를 임의로 바꿔도 서버 정책이 일관되게 적용되어야 한다.
- 세션 탈취를 가정한 요청은 서버가 다시 권한을 확인해야 한다.

## 8. 로그와 감사 추적

기록 대상:

- 로그인 / 로그아웃
- 관리자 생성 / 삭제
- 권한 변경
- Owner 이전
- 프로젝트 생성 / 설정 변경
- 참가자 추첨
- 강제 스킵 / 일시정지 / 재개
- 최종본 다운로드

### 원칙

- 로그는 일반 Admin이 임의 삭제할 수 없어야 한다.
- 중요한 관리자 행위는 시각, 실행자, 대상이 남아야 한다.

## 9. 데이터 무결성

자동 검증 대상:

- `Owner 수 = 1`
- 관리자 ID는 모두 unique
- 삭제된 관리자에게 유효한 세션이 남아 있지 않음
- `Owner` 이전 후 역할이 정확히 반영됨
- DB 재시작 후에도 관리자 데이터가 유지됨

## 10. 배포 전 체크리스트

- [ ] 최초 관리자 생성 가능
- [ ] 최초 관리자 = Owner
- [ ] 초기 설정 재실행 차단
- [ ] 로그인 / 로그아웃 정상
- [ ] 세션 유지 / 폐기 정상
- [ ] Admin 생성 / 삭제 권한 정상
- [ ] Owner 자신 삭제 차단
- [ ] Owner 이전 원자적 처리
- [ ] Owner는 항상 정확히 1명
- [ ] 참가자 → 관리자 API 차단
- [ ] Admin → Owner 조작 차단
- [ ] 비밀번호 해시 저장
- [ ] Rate limiting 적용
- [ ] 관리자 로그 기록

## 11. 최종 핵심

1. `Owner`는 항상 정확히 한 명이어야 한다.  
2. `Owner`만 관리자 권한을 관리할 수 있어야 한다.  
3. `Owner` 이전은 원자적으로 처리되어야 한다.  
4. 모든 권한 검사는 서버에서 해야 한다.
