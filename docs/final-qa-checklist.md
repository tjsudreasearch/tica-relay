# TiCa Relay 최종 구현 검수 체크리스트

이 문서는 개발 완료 후 실제 운영 전에 `PASS / FAIL / 수정 완료 / N/A`로 확인하는 최종 QA 문서다.

현재 운영 원칙은 **학교 내부 전용**, **TXT only**, **Owner 승인 기반 관리자 인증**이다. 따라서 PDF 다운로드 항목은 요구사항에서 제외하고 `N/A`로 처리한다.

## 체크 방식

| 상태 | 의미 |
| --- | --- |
| `PASS` | 요구사항이 구현되어 있고 실제 테스트를 통과함 |
| `FAIL` | 요구사항이 구현되지 않았거나 테스트 실패 |
| `수정 완료` | 실패 후 수정했고 재테스트 통과 |
| `N/A` | 현재 TiCa 운영 범위에서 제외한 항목 |

| [ ] | 같은 개인 링크를 두 브라우저에서 동시에 사용해도 데이터가 꼬이지 않는다. |
| [ ] | 두 관리자가 동시에 스킵해도 한 번만 처리된다. |
| [ ] | 관리자 스킵과 참가자 제출이 동시에 발생해도 데이터가 꼬이지 않는다. |
| [ ] | 두 명이 동시에 Owner 이전을 시도해도 Owner는 한 명만 유지된다. |
| [ ] | 최초 Owner 생성 동시 요청에도 Owner는 한 명만 생성된다. |

## 24. 보안 최종 검증

| 상태 | 항목 |

| [ ] | 참가자가 전체 원고를 요청할 수 없다. |
| [ ] | 참가자가 자신의 순서를 알 수 없다. |

| [ ] | 삭제 또는 정지된 관리자 세션은 무효화된다. |
| [ ] | 모든 민감한 권한 검사는 서버에서 수행된다. |
